# Public experimental intermediate build transfer

This is not a tested client or an official release. Producer A normally completes dependencies and the first 150 engine objects from the fixed reviewed public source and official tools. Continuation R restores that exact package, completes only the next 300 objects, and seals the cumulative first 450. Final B restores R's exact package, builds the client and then the test targets in the same directory. Both post-build mathematical goldens and all four CTests remain required before final client publication.

All three roles use one reviewed allocation recipe and driver manifest. Each consumer requires the separately reviewed artifact URL, whole-file and inner size/SHA256, producer/config/source/tool identities and exact object prefix. R's new package binds its exact predecessor A in both inner and outer metadata. Final B accepts only the separately pinned R package and its reviewed A predecessor. Earlier packages from a different driver manifest are not silently accepted.

The outer package contains only checkpoint.zip, TRANSFER_RECEIPT.json and material/. The material directory supplies the selected corresponding source, rebuild information, notices and LEGAL.md. It does not grant a repository-wide open-source license or upstream endorsement. Retain applicable third-party notices and consult upstream LEGAL.md. The fixed experimental distribution review does not imply permission for arbitrary redistribution.

Objects, libraries, Ninja metadata and structured provenance can contain fixed provider paths and compiler metadata. This is not a confidentiality boundary or an arbitrary-source sandbox. No ordinary logs, PDBs, credentials, user files, SDK/tool binaries or arbitrary workspace content are included. Only fixed reviewed sources and tools run on the fresh controlled worker.

Native cache restore/save are disabled throughout all three jobs. Successful entrypoint completion uses Exit-AppveyorBuild with APPVEYOR_SKIP_FINALIZE_ON_EXIT=true and never flips cache controls. No native cache entries are declared or manipulated. All supplied execution contracts are inert until separately reviewed activation. Neither runtime compatibility nor successful provider execution is established by local tests.

A and R each upload exactly one resume-transfer.zip only after complete owned workspace cleanup. An uncertain upload is not retried automatically. Each consumer's artifact pin must refer to its exact reviewed producer, never a latest-build URL. Outer maximum is 400,000,000 compressed bytes. Limits and the 3300-second driver deadline can block completion; no successful build is promised.

The allocation reduces A's compile time relative to the observed 300-object attempt and leaves final B about 528 engine objects on the observed 978-object graph. This count is a workload observation, not a compile-time upper bound. Restore, sealing, final links, tests and packaging have not all been measured on Windows. No acceptance test or deadline is removed, and successful completion of all three jobs is not promised.
